## What shipped

- **Deterministic scope gating** (`lenses_for`): tier floors (D1 functional-testing; D2/D3
  testing + maintainability; D4 + the full never-gate class) plus flag-triggered lenses
  (security_boundary → security + adversarial; privacy; data_migration; release; user_facing →
  ux + accessibility + visual-design; api_change; performance; journey; new_dependency →
  security; irreversible recorded). **Every skipped catalog lens carries a reason** — no
  silently skipped lens.
- **Dispatch** (`dispatch_assurance`): fresh-context lens runs with an **anti-anchored
  payload** (artifact + lens + requirement only — asserted: no packet/claims/summary/
  confidence); coverage statements required; findings land through the standard pipeline
  (fingerprint dedupe + multi-lens confirmation from 5.3); **Sentinel rule** — the security
  lens cannot be skipped for a security boundary; advisory quality score computed.
- **The gate** (`gate`): deterministic over recorded findings — blockers always block;
  criticals block **while live** (a finding stays live — `open` — until a guarded resolution
  retires it; multi-lens corroboration strengthens a finding and never clears it); findings from
  the never-gate class are **unwaivable by Kel**; returns reasons (severity, id, status, lens),
  never-gate hits, and the advisory quality score; byte-stable across calls.
- **Waivers** (`waive_gate`): constitutional (doc 09 §2/§10) — only `authority='user'` can
  accept never-gate findings; kel waivers are refused while those are open; accepted findings
  are recorded with the waiver reason.
- **Oracle harness** (`oracle_check`): adversarial lens run under family independence
  (different provider family required; same-family fallback only when explicitly recorded);
  coverage statement required; findings through the standard pipeline.
- **Learning data** (`lens_stats`): per-lens status counts + FP rate over true false positives
  only (risk acceptances are counted separately, and the never-gate lenses are not learnable),
  read-only.
- **Carries (audit 15, suggestions 1–2)**: `messages.ESCALATION_TYPES` is the single source
  (pods imports it; identity-asserted in tests); the boundary test enumerates all three
  escalation types at cap and refuses HANDOFF at cap.

**Behaviour changes recorded here (not silent):**

1. A multi-lens corroborated finding stays `open` and keeps blocking. The `confirmed` status
   remains part of the schema vocabulary (and is treated as live on read, defensively) but the
   pipeline no longer writes it; corroboration lives in `confirmations`/`confidence`.
2. `gate()['reasons']` now carries the finding's status as well as severity, id and lens, so the
   reason string is no longer byte-identical to the original 5.4 shape.
3. `dispatch_assurance` / `oracle_check` require `mission_id`; `lens_stats` reports `accepted`,
   `false_positive` and `learnable`, and its `fp_rate` covers true false positives only.

Status: implemented + engine-verified on `ux/v15-journeys` (commit `5f77f42`); audit requested
for `71122ef..5f77f42`. New additive migration (19); no live caller — parallel streams require an
explicit mission decision (D3/D4) and the whole module is inert otherwise.

## What shipped

- **`kel/parallel.py`** (new, migration 19 `v16-workforce-parallel`; three tables —
  `mission_streams`, `mission_leases`, `stream_announces` — with append-only triggers on the
  announce ledger only; leases and streams are *live state* and must be mutable):
  - **Isolation** — `open_stream` creates one snapshot workspace per stream with
    `coding.snapshot` (tracked + untracked state, never the source checkout), and records the
    base commit plus the stream's declared write paths.
  - **Decomposition statement (doc 05 R9)** — `plan_streams` refuses anything the later steps
    would have to guess about: 2..3 streams (D3's "up to three parallel streams"; R8's worker
    cap), unique names, a non-empty objective, non-empty *relative* write paths (absolute,
    drive-letter, `~` and `..` forms are refused before any normalisation), pairwise-disjoint
    paths (a declared overlap is refused, so two streams can never be handed the same territory)
    and an explicit merge strategy.
  - **Mission leases** — `acquire_lease` (one live lease per stream; refused when another live
    lease overlaps the stream's paths; a lapsed overlapping row is retired in the same
    transaction), `heartbeat` (a retired *or lapsed* lease can never be revived),
    `reclaim_stale_leases` (heartbeat expiry, mirroring the runner pattern), `release_lease`
    (`RELEASED`/`REVOKED` with a reason). `assert_writable` is the single fail-closed check on
    every write *this module performs*: the lease must be live, unexpired, its own, and the paths
    must sit inside what it declared. A worker's own filesystem writes are **detected, not
    prevented** — a callable cannot be policed — and are reported (see `undeclared_writes` and
    `integrate` below; audit 20 corrected the earlier wording that read as prevention).
  - **`run_stream`** — refuses anything but that stream's live lease, and refuses paths outside
    what that lease declared; the worker receives the stream, the allowed paths and the lease; the
    module owns the accounting.
  - **Announce chain** — `close_stream` (once), then `announce` appends a row chained to the
    mission's previous announce (seq, previous, digest, summary, paths) in the append-only ledger;
    the digest is taken over the stream's **staged change set** and an announce of a path the
    stream did not change is refused; `announce_chain` verifies the links; `synthesize` produces
    the ordered report with the merged path set and digest.
  - **Integration** — `integrate` stages each finished stream's own copy, applies its patch to a
    fresh integration snapshot (the default is `git apply`; a caller-supplied `integrator` hook
    replaces it and a falsy return is a conflict), and reports a *conflict* rather than guessing
    (a declared overlap, a changed-path overlap, or a patch the merge refuses). `conflict_metrics`
    reports `declared_overlaps` (plan-level; non-empty means the plan was tampered with),
    `actual_overlaps` (what the streams really changed), per-stream `undeclared_writes` and
    `conflict_count`/`conflict_rate`.
  - **`run_parallel`** — the hands-off D3 flow: plan → open → lease → run → close → announce in
    order → integrate → synthesize → metrics. Parallelism is a **D3/D4 capability** (doc 05); a
    lower tier is refused rather than silently serialised. A failing worker abandons its stream
    and revokes its lease.
- **`service.py`** applies migration 19 at startup beside 16/17/18.
- **`evaluation.py`** (doc 13 class-3 readiness): a `'3'` pilot class ("large parallel feature",
  D3 features, a seeded integration-seam defect). Config A stays the single agent; config C runs
  the D3 parallel mission and its integration check detects the seam and records it as a finding,
  so the existing pilot gate (`escaped_C < escaped_A`) applies unchanged.

## Defects found by the tests (fixed in this commit, with regressions)

1. **Path traversal was accepted**: `_clean_path` stripped a leading `/` *before* the absolute
   check, so `/etc/passwd` became an accepted relative path. Absolute, drive-letter and `~`
   forms are now refused before normalisation.
2. **Untracked stream output was invisible to the integration check**: changed-path detection
   used `git diff`, which reports nothing for a stream's new files, so a real overlap could
   produce an empty patch and an "integration_ok" with nothing applied. Detection now uses
   `git status --porcelain` and `integrate` stages the stream copy before diffing.

## Deviations / notes

1. **No scheduler**: `run_parallel` runs streams in plan order. A caller that wants wall-clock
   concurrency runs its own workers in threads; what this module guarantees is the *lease*, not
   the parallelism. (The doc's "disjoint-write parallelism" is enforced as disjointness, which is
   the property that survives contact with a real scheduler.)
2. **Leases and streams are mutable rows, announces are not.** The append-only trigger applies to
   `stream_announces` only; a lease that could not be updated could not express liveness.
3. `integrate` stages the *stream's own* copy before diffing (documented in code); the source
   checkout is never touched — `coding.snapshot` semantics are unchanged.
4. **Non-goals honoured**: no depth-2 spawning, no worktree *leases outside the mission copy*
   (the lease governs the mission's own snapshot directories, not the user's checkout), no
   real-model campaign (the class-3 pilot uses deterministic fixtures).
5. The exit criteria's "H2 gains on classes 3/5/9" and "conflict rate no worse than baseline B"
   ride the full doc-13 matrix (>=90 runs, configs A/B/C); this increment ships the machinery and
   the class-3 pilot, not the campaign.

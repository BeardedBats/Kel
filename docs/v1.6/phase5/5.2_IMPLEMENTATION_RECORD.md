## What shipped

- **Staffing decision v1** (`staffing.py`): deterministic `score()` over the 11-feature
  vector plus the budget label; `decide()` maps to tier bands (D0 ≤2 … D4), applies the R1
  cap (undecomposable/sequential work stays at most a pod), flag floors (R3–R7 via mission
  flags), `tier_max`, and records every reason and fired rule. D0/D1 are the supported
  outcomes; D2+ is returned so the caller refuses explicitly.
- **D1 delegation** (`delegation.py`): migration 18 adds `task_contracts.milestone_id`
  (doc 14 "keyed to milestone"; additive ALTER + index + bookkeeping). `delegate()`: flag
  check (off → zero writes), job/milestone validation, staffing decision, contract built from
  the milestone's engine checks (+ artifact criterion) with role-derived authority, validated
  against registry ceilings, frozen into `task_contracts` (append-only triggers), optional
  reserve-before-spawn, exactly one `assign_worker` assignment, then `staffing.decided` +
  `contract.issued` events (reasons included).
- **Evidence-bound close** (`close_d1()`): the packet is validated structurally, then every
  claim's evidence must exist in the ledger, be fresh (stricter of contract window vs row
  window), content-bound (digest among delivered artifacts) and command-bound where required,
  and every acceptance criterion must map to a verified claim — a `completed` close on any
  gap is refused ("stale-evidence closes impossible", tested). failed → FAILED;
  uncertain/blocked → UNCERTAIN; double closes refused; the close is recorded as
  `task.closed` and the assignment state moves accordingly.
- **Fixture orchestrator** (`run_d1()`): enforces declared worker tools ⊆ frozen grants
  *before* the worker runs (S6); runs exactly one worker (no nested spawning — the workforce
  tool vocabulary has no spawn tool); worker errors close as `failed` with the exception
  class recorded (never a fabricated success).
- **Ledgers** (`task_ledger()`, `progress_ledger()`): read-only projections joining
  `task_contracts` ↔ `contract.issued` ↔ `team_assignments` ↔ `task.closed`, plus milestone
  state/attempts from the job and the evidence list; no new persistence.
- **Carry-forward closed**: N7 (`registry_ceilings(project_id, task_id)` resolves through role
  overrides), Sug1 (fallbacks without verifiable models filtered when requirements are
  enforced), Sug2 (`link_reservation` conditional UPDATE + already-linked refusal), Sug3
  (`local_only` override-off refused), Sug4 (falsy `extra` rejected; cycle comment), S3
  (shared `workforce_fixtures.py`; both test files refactored onto it).
- **Service wiring**: migration 18 ensured at startup next to 16/17.

## Deviations / notes

1. `D1_BUDGET_DEFAULTS` are conservative v0 numbers (overridable per delegation); real
   budget-class envelopes arrive with doc-10 calibration.
2. D1 contracts carry `required_reviewer.lenses: []` — independent verification is the 5.3
   (D2) increment; the close relies on engine-check criteria plus evidence binding.
3. `delegate()` requires an explicit feature vector (callers own feature extraction for now;
   automatic extraction rides later increments).
4. Task↔assignment joins run through the `contract.issued` event because `team_assignments`
   stores no task column (schema unchanged by design).

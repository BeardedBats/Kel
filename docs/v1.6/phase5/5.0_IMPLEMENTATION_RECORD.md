## What shipped

- Migration **16** (`v16-workforce-schemas`), additive and idempotent, applied at Service
  startup next to the other feature ensures:
  - `task_contracts` — TaskContract snapshots, keyed `(task_id, version)`; immutable at the
    storage layer (append-only triggers refuse UPDATE/DELETE — frozen at claim).
  - `workforce_messages` — append-only typed messages (edits are new rows with `supersedes`).
  - `findings` — review findings (workforce-os doc 08 §5); workflow state stays mutable.
  - `evidence_records` — append-only evidence ledger (command-bound classes; freshness window
    stored, freshness computed on read).
  - `skill_packs` — version catalog; an existing `(name, version)` content is immutable.
- Pure modules (`runtime/kel/`):
  - `workforce.py` — schema owner, id vocabulary, hidden-reasoning/secret scan
    (`find_unsafe`/`assert_safe`, reusing the team contract and the memory scanner),
    skill-pack registry (`register_skill_pack`).
  - `contracts.py` — `validate_task_contract` / `validate_completion_packet` (v1, per doc 06;
    trusted verification methods only — executable oracles stay forbidden; authority may only
    narrow the role ceiling, never widen it).
  - `messages.py` — protocol v1 validation (9 types; STATUS is deliberately not one; refs
    required; summary ≤400, details ≤2000; staffing requests state budget impact).
  - `evidence.py` — `write_evidence` + `freshness()` + `content_bound()`.
  - `assurance.py` — 15-lens registry (doc 08 §1), never-gate set, `validate_finding`,
    `quality_score`.
  - `staffing.py` — R1–R10 hard-rule table, caps, weights, budget classes (data only; no
    scoring or staffing behavior yet).
- Service wiring: `runtime/kel/service.py` gains one import + one `ensure_workforce_schema`
  call (8-line insertion; see the commit diff).

## Documented deviations from the design shorthand

1. **`task_contracts` (not `contracts`)** — `core.py` already owns a `contracts` table (job
   contract versions). The workforce TaskContract ledger is named distinctly so the two
   records never mix. Same table set otherwise.
2. **Interim static role→authority ceilings** (`contracts.ROLE_MAX_AUTHORITY`) — the charters
   use richer words (artifact_write, deploy_gated); these map to the doc-06 enum until role
   registry v2 (increment 5.1) carries ceilings as versioned role data.
3. **Append-only triggers** — no prior trigger usage in this repository; added on the three
   ledgers so the storage layer itself cannot rewrite history (doc 07: corrections are new
   rows, never silent edits).

# Phase 5.1 — Agent-to-model assignment (implementation record)

Increment: **5.1 — Agent-to-model assignment** of Phase 5 (Workforce OS), per
`ux-audit/workforce-os/15_PHASE5_IMPLEMENTATION_SPEC.md` §1–§2 and the architecture map in
`14_KEL_ARCHITECTURE_INTEGRATION.md`; schema per doc 03 §7–§8 (role registry v2), doc 10
(requirements, modes, overlays, budget governor).

Status: implemented + engine-verified on `ux/v15-journeys` (commit `9d6ed55`); audit requested
for `cc909b9..9d6ed55`. No live flow calls the new API yet (D1/5.2 wires it); the
`workforce.enabled` flag defaults off and is recorded in every assignment snapshot.

## What shipped

- **Role registry v2** (`kel/assignment.py`): the 8-archetype roster ships as 7 spawnable
  role templates (`discovery`, `architect`, `designer`, `builder`, `verifier`, `sentinel`,
  `release`) seeded idempotently into the existing V1.4 `role_templates`/`role_versions`
  storage; Commander is Kel itself and is documented as never-a-template. v2 fields per doc
  03 §7: `authority_max`, `capability_requirements`, `dispatch_tier`, `budget_class`,
  `default_skill_packs`, `independence`, `anti_patterns` — validated by
  `validate_role_fields_v2` (team._validate_fields stays schema-light; values validate when
  a role is used for assignment).
- **Routing modes** (`resolve_binding`): AUTO delegates to the existing deterministic
  eligibility + cost policy (`router.select`); PREFERRED honors a caller-ordered candidate
  list with recorded fallbacks (and refuses when no preferred entry is eligible); FIXED
  validates the pin and never substitutes (ineligible pins are refused with reasons).
  Requirement profiles map doc-10 requirement tokens onto provider capability tokens;
  requirements with no declared token yet (`web_research`, `image`, `audio`) fail closed with
  readable exclusions; `long_context` / `structured_output` are recorded as advisory (no
  token exists yet — never silently dropped).
- **Capability grants (fail-closed)**: `TOOL_AUTHORITY` matrix (product-effect semantics:
  reading/browsing/research-APIs/check-runs are read-only; writes and git need
  workspace-write; installs and shells need a lease). `require_grants` refuses any role whose
  tool policy exceeds its authority ceiling; the resolved grant set is frozen in the snapshot.
- **Budget reservations** (migration 17, `v16-budget-reservations`): `reserve_budget` /
  `release_budget` / `link_reservation` / `reservations`; reserve-before-spawn linkage is
  recorded in the assignment snapshot; invalid classes/amounts/unknown jobs are refused.
- **Overlays v1**: registry keyed `provider:model` with `provider:*` family fallback; empty
  by design (no-op when absent — graceful degradation); subordinate to role/skill
  instructions (documented).
- **Assignment snapshots**: `team.create_assignment` accepts `extra` and the workforce record
  (mode, binding, grants, budget_class, dispatch_tier, role ceiling, reservation id, flags)
  is frozen into the snapshot; later role edits never rewrite it (tested).
- **Contract ceilings**: `validate_task_contract` accepts `ceilings=`; `registry_ceilings`
  derives the table from the versioned registry and matches the 5.0 static map for all seven
  worker roles (the 5.0 "interim until 5.1" note is now closed).
- **Service wiring**: migration 17 ensured at startup next to migration 16.

## Documented deviations / notes

1. **Capability grants are a deterministic matrix + recorded resolution, not a table** —
   doc 14 §3's complete table list deliberately excludes a grants table; the effective grant
   set is frozen into each assignment snapshot instead (audit trail without new persistence).
2. **Advisory vs fail-closed requirements** — see above; each binding records enforced vs
   advisory requirements, and exclusions list reasons.
3. **`default_skill_packs` are names-only refs in v1** — pack version binding lands when pack
   content ships (5.2+); the catalog exists since 5.0.
4. **Flag storage** — `workforce.enabled` is env-driven (`KEL_WORKFORCE`, default off) and
   recorded per assignment; per-project flag storage arrives with the first live consumer.

## What shipped (scope)

- **Builder→Verifier hand-off** (`kel/pods.py: run_d2`): a D2 staffing decision gates the pod;
  the builder task and a dependent verifier task each get a frozen contract
  (`issue_task_contract`: verifier criteria are verification-specific, reviewer lenses =
  functional-testing + maintainability, `dependencies.tasks = [builder_task]`) and exactly one
  assignment each (Builder ≠ Verifier structurally and by id); the verifier binding prefers a
  different provider family (recorded `family_diversity: different|unavailable`); the builder
  closes evidence-bound, a HANDOFF message goes out, the verifier runs the two lenses, records
  findings, and returns a verdict; a VERIFIED verdict is refused while blocker/critical
  findings are open; both assignments close through `close_d1` (stale/unbound evidence stays
  impossible); stall probes run while each phase is ACTIVE; interruptions are counted from the
  message ledger.
- **Findings v1 (two lenses)** (`kel/assurance.py`): `record_finding` (validated, fingerprint
  dedupe — same-lens duplicates refused, multi-lens confirmation upgrades with the +1 cap and
  `confirmed_by_multi`), `resolve_finding` (arbitration ladder v1 — `fixed` needs a recorded
  evidence row; `accepted`/`dismissed` need a rationale; blockers additionally need evidence,
  because a lower rung never overrides a higher one without new evidence), read-only reader.
- **Message protocol v1** (`kel/messages.py`): `send_message` dispatch enforcement — worker
  pair budget ≤ 6 (cmd is the exempt escalation channel), task budget ≤ 12, fingerprint dedupe
  (same refs + required_action), receiver-state guard (cancelled assignments), append-only
  rows; identity validation matches the engine's real `uid()` ids as well as the design's
  prefixes.
- **Stall detection v1** (`kel/pods.py: check_stall`): an ACTIVE assignment with no recorded
  activity beyond the threshold → `stalled: true` with idle minutes; non-active states return
  why not.
- **Evaluation-harness pilot** (`kel/evaluation.py`): configs A (single specialist, no
  verification) vs C (D2 pod) on classes 2/6/8 with deterministic fixtures and seeded defects;
  records seeded/detected/escaped, verdicts, and interruptions; per-class gates are
  `escaped_C < escaped_A` and interruptions within budget.

on clean runs are 0 ≤ budget.

# Phase 5.7 — adaptive staffing enablement: DECISION (deferred)

Date: 2026-09-18. Decision: **DEFERRED — entry conditions are not met.**

Spec entry conditions (`15_PHASE5_IMPLEMENTATION_SPEC.md` §5.7; doc 11 §5): the 5.6 validation
metrics over a full campaign window, the doc-13 evaluation campaign pass, and explicit user
sign-off.

Current evidence: Phase 5.6 (shadow) is accepted (through `8a2b25d`) and its metric views exist
(gating precision, false-skip by recomputed gating plans; performance stats with small-sample
labels), but **no campaign window exists** — the doc-13 full matrix (10 classes × 3 configs ×
≥3 seeds; pilot classes 2/3/6/8 only so far) is a carried item, and there is no user sign-off.
Enabling adaptive gating now would fabricate readiness.

Disposition: nothing enables. `workforce.gating.adaptive` stays off; the shadow loop keeps
recording observations so a future campaign window can be evaluated. Re-entry checklist:

1. run the doc-13 campaign (classes 3/5/9 gains; baseline-B conflict rate);
2. evaluate the pre-registered H1-H5 outcomes plus the 5.6 metrics over the campaign window;
3. bring the results to the user for explicit sign-off;
4. only then open the §5.7 implementation (non-insurance gating + ceremony adaptation,
   changelog + single-flag rollback; never-gate insurance is untouchable).

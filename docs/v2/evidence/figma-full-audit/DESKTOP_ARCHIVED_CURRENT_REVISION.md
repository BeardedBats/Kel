# Desktop Archived and Select — current Figma revision

Current Figma [Archived `314:19219`](https://www.figma.com/design/BlpVvZGuc9j9HhxUojIiJI/Kel-Design-System?node-id=314-19219) and [Select `314:19647`](https://www.figma.com/design/BlpVvZGuc9j9HhxUojIiJI/Kel-Design-System?node-id=314-19647) were read directly. Desktop now places Select beside the Archived heading and groups rows inside glass cards. Delete and Unarchive use the visible text actions in Figma. Select shows the count, Cancel, a red Delete count action, and blue checked boxes. The existing archive, unarchive, pagination, and confirmation paths remain in use.

The final disposable Windows package rendered a three-chat response intercepted only for `GET /api/sidebar?archived=true`. It covered a two-chat project and one no-project chat. The [1440px view](DESKTOP_ARCHIVED_PACKAGE_1440.png) placed the cards at x613/y183, 670×160 and x613/y355, 670×104. The [800px view](DESKTOP_ARCHIVED_PACKAGE_800.png) used x371/y179, 388×160 and x371/y351, 388×104. The [selected 1440px](DESKTOP_ARCHIVED_SELECT_PACKAGE_1440.png) and [800px](DESKTOP_ARCHIVED_SELECT_PACKAGE_800.png) views showed two checks and an enabled red Delete 2 action. Clicking it opened the real confirmation; the check canceled it. Both widths had zero overflow and renderer errors.

The synthetic response included `archived_at`, so the screenshots show Archived timestamps. When a backend row lacks that field, the screen labels its creation time **Created** instead of inventing an archive date. No real archived item was deleted, restored, or changed. The canonical Data root was untouched.
